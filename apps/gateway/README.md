# gateway

```
migrations/   D1 migrations, generated by drizzle-kit from src/users/schema.ts
src/
  index.ts    Worker entry; the only file that touches Cloudflare bindings
  app/        Hono app: sandbox hostnames → owner's sandbox, app.<domain> → account, else /admin
  account/    Signed-in routes on app.<domain>: home page, /api/me, pairing
  access/     Cloudflare Access identity (ctx.access) → email
  admin/      Admin API: users, GitHub installations, pair, status, stop
  users/      D1 schema and user store (Drizzle), sandbox name rules
  pairing/    Pairing links for a sandbox
  routing/    Hostname → app, sandbox name or gateway
  sandbox/    Durable Object, container lifecycle and outbound handlers, one per sandbox
  github/     GitHub App tokens and which outbound requests get them
  config/     wrangler.jsonc vars, validated with valibot
  errors/     Error codes, statuses and messages; errorResponse()
  log/        Logging
  http/       HTTP status and WebSocket close codes
  testing/    Test-only helpers: Drizzle on node:sqlite with the real migrations
```

Rules:

- Import other folders through their `index.ts` with `@/name`; use `./file.ts` inside a folder.
- Only `index.ts` and `sandbox/` use the Workers runtime. Everything else is tested with `vp test`.
- No type casts (`as`, `!`), braces on every `if`, sorted imports. `vp check` enforces these.
- Validate outside data with valibot.
- Query D1 with Drizzle; change the schema in `src/users/schema.ts`, then run
  `vp run gateway#db:generate --name <change>` and commit the generated migration. Use
  `.limit(1).all()` instead of `.get()`; the test database can't return a missing row from `.get()`.
- A sandbox's Durable Object is named by its user's ID, never the sandbox name or anything else
  from the request. Only the hostname (sandbox hosts) or the Access identity (app host) picks it.
- Throw `GatewayError(ErrorCode.X)`, log with `log`, use `HttpStatus` and `WebSocketClose`.
- Comments only for TODOs and links to the docs code was taken from.
- OpenCode is pinned in `sandbox/Dockerfile` and `pnpm-workspace.yaml`; update both together.
